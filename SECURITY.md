# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected security vulnerability. Until a
dedicated reporting channel is published, contact the project maintainer
privately through the repository hosting platform and include:

- a concise impact description;
- the affected version or commit;
- safe, non-destructive reproduction steps; and
- any proposed mitigation.

Do not attach malware, credentials, memory dumps, or personal data. Use
harmless synthetic inputs or official EICAR/AMSI artifacts when demonstrating
a finding.

## Scope

Reports about unintended process modification, sample execution, persistence,
privilege escalation, unsafe logging, exposed personal paths, or dependency
provenance are in scope.

Supported versions and response targets will be published only after the
release-readiness gate is closed.
