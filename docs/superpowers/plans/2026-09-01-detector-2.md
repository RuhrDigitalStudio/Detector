# Detector 2.0 implementation plan

> Execute in order with tests written before production behavior. Commit each task separately.

**Goal:** Turn the existing scanners into an explainable Blue-Team case workbench for static artifact triage and imported runtime evidence, with a useful GUI and release-ready documentation.

**Safety constraint:** Never execute an inspected sample. Process inspection stays read-only. Runtime behavior is either observed from already-running system activity or imported from an isolated environment.

---

## Task 1: Case model, deterministic export and bounds

**Create:**
- `src/Detector.Core/Analysis/AnalysisCase.cs`
- `src/Detector.Core/Analysis/AnalysisCaseBuilder.cs`
- `src/Detector.Core/Analysis/CaseExporter.cs`
- `src/Detector.Core/Analysis/AnalysisLimits.cs`
- `tests/Detector.Tests/AnalysisCaseTests.cs`

Write failing tests for indicator de-duplication, stable ordering, coverage gaps, JSON round trip, HTML encoding and collection limits. Implement records and a builder that accepts existing `Detection` values without changing their public shape. Export indented stable JSON and standalone HTML with no script execution or external assets.

**Verify:**

```powershell
dotnet test tests/Detector.Tests/Detector.Tests.csproj -c Release --filter AnalysisCaseTests
```

**Commit:** `feat: add bounded analysis case reports`

## Task 2: Static artifact and metadata-only .NET/PE analysis

**Create:**
- `src/Detector.Core/Analysis/ArtifactAnalyzer.cs`
- `src/Detector.Core/Analysis/PeArtifactAnalyzer.cs`
- `src/Detector.Core/Analysis/SourceAnalyzer.cs`

**Verify:** focused tests plus the complete suite.
